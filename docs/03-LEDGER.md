## מה נבנה (S1) - הכרעות ששווה לזכור
- ערכי אירוע נשמרים כ-JSON (`vals`; `values` היא מילה שמורה ב-SQL) לפי מזהה שדה, כדי שסוגים ושאלות יהיו ניתנים לעריכה בלי מיגרציה.
- `lastMedEvent` מחפש ב-JSON עם LIKE. מספיק לנפחים של אפליקציה אישית; אם יגדל, להוסיף עמודה `med_id`.
- פופאפ התיעוד זוכר בחירה אחרונה לפי `remember_last` של כל שאלה; טיטול וצד הנקה לא זוכרים (בכוונה).
- שאלון אחרי תור נפתח משלושה מקומות: התראה שעה אחרי, כרטיס במסך הבית, ולחיצה על התור ביומן.

## S2 - הכרעות
- כל טבלה מסונכרנת: מזהה TEXT אקראי, `updated_at`, `deleted` (tombstone). מיזוג: updated_at גבוה מנצח.
- קובץ JSON אחד לכל מכשיר בתיקיית "יומן אירועים - נתונים" בדרייב; כל מכשיר קורא את כולם וכותב רק את שלו - בלי התנגשויות כתיבה.
- תבניות עם מזהים קבועים (tpl-...) ו-updated_at=1 כדי ששני מכשירים לא ישכפלו סוגים.
- scope `drive.file`: האפליקציה רואה רק מה שיצרה. שיתוף בין אנשים שונים דורש scope רחב יותר (שאלה פתוחה Q-3).

## לקחים ממוספרים
- L-1: `flutter create` בסביבת Claude תוקע ב-pub get גם עם `--no-pub` כשרץ בתיקייה קיימת. לייצר שלד בתיקייה זמנית עם `--offline` ולהעתיק את `android/`.
- L-2: artifacts של GitHub Actions יושבים ב-Azure blob שחסום לסביבת Claude. פרסום כ-Release עוקף את זה למשתמש; ל-Claude עצמו גם Release חסום להורדה. בדיקת sha256 נעשית בטלפון או בגיליון.
- L-3: מחבר Drive לא מעדכן תוכן של קובץ קיים. לכל עדכון: יצירה מחדש + אשפה לישן. לתעד מזהים ב-RESTORE.
- L-4: בלי keystore קבוע, CI מייצר מפתח debug חדש בכל ריצה - עדכון APK לא מותקן מעל הקודם. תוקן ב-D-14 (keystore קבוע מ-Secrets).
- L-5: API ה-secrets של gh חסום בפרוקסי (403). מגדירים Secrets דרך ממשק GitHub בכרום של המבקש.
- L-7: החלטות זהות (שם, לוגו, עיצוב, פונטים) הן של המבקש. שואלים לפני שבונים, גם כשנראה שיש ברירת מחדל סבירה.
- L-6: כשמשנים applicationId או מפתח חתימה, חובה להסיר את הגרסה הישנה מהטלפון (והנתונים בה אובדים אם לא גובו).
